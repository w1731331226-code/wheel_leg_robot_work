# 失败链诊断：先对齐失败反馈，不追加训练

## 结论与边界

本轮用 MuJoCo Warp GPU 对4个已公开开发场景、2个固定检查点各回放一次，按2kHz记录完整物理步。没有训练、重选权重、修改控制权限或放宽成功门。八条轨迹只用于定位事件顺序，不能估计泛化成功率，更不能证明策略优化。

直接证据确认两个机制：**5°不可逆失败与终端反馈相隔0.7375～4.8700秒；轮电机基础命令超速度包络会全通道清零策略残差，部分清零时刻仍有符合原电机边界的残差余量。** 前者优先进入单因素验证；后者独立保留，不能同时修改。尚未证明任何一个机制是失败的唯一原因，或修正后能满足用户要求的大幅、稳定成功率提升。

## 数据与非侵入性检查

- 原策略：terrain-v3第3轮中点；训练后策略：既有virtual6的2,048,000步末点。精确检查点路径在 `summary.json`，场景来自 `../virtual6_capability_20260922/baseline.json` 的700000、700102、700202、700302，未打开720000留出集。
- 每个检查点同时回放这4例；策略推理在CPU，物理在GPU。不是新1024环境训练。既有动画和总览未改动。
- 记录首次目标地形轮接触、实际接触法向力与接触点切向滑移、策略目标/滤波值、限幅前后基础扭矩、请求/执行残差、具体受限电机、姿态、逐项奖励和结束原因。每个NPZ自带列名。
- 控制器只增加可选的6列限幅前数值输出，默认15列路径和全部控制公式不变。独立记录类复用原环境更新顺序，不替换训练入口。
- 单世界50个策略步（1秒）原环境/记录环境对照通过：观测与奖励绝对误差≤1e-6。此短检查位于接触前，**不证明完整接触轨迹逐位等价**；接触求解/批次敏感性仍需保留。
- 八条归档记录均通过有限值、0.5ms连续时间、物理步数、实际残差=λ×请求残差、全局基础不可行标记=速度限幅掩码非零、回报总和=episode.r检查。独立重建连续奖励后，剩余值与原终端±10吻合，最大误差1.42e-14。
- 接触力与接触点速度采用求解器的接触/积分前运动学，姿态是该步积分后值；相邻量存在至多一个物理步（0.5ms）的时间对齐差。目标接触计数采用穿透或正法向力条件，不把轮速差代理称作实际滑移。

## 奖励错位的具体程度

原始回报精确分解为：速度奖励 − 姿态二次代价 − 残差幅度代价 − 残差变化代价 + 终端奖励。原训练入口也关闭了奖励归一化；以下折扣按50Hz策略步、gamma=.99计算，但**不是PPO优势或梯度重建**，未包含价值函数bootstrap与优势标准化。

代表轨迹六维700000只短暂偏航超过门（峰值5.1976°），随后恢复并完成，已不可成功却又运行3.848秒。整段原始回报为8.8693−0.6803−0.0011−0.0093−10=−1.8214；从回合起点折扣后的越界及后续净回报仅−0.00388，后续速度正奖励几乎抵消终端惩罚。

反例原700102持续姿态失稳，姿态代价189.8944，原始总回报−190.9760；原700302提前跌倒，姿态代价17.0036，原始总回报−21.6485。这说明失败轨迹间排序高度受持续时长/后续姿态影响，**不同轨迹的比较不证明策略主动选择跌倒**。

八条轨迹残差幅度代价仅0.00046～0.00255，变化代价0.00303～0.03001，姿态代价0.14695～189.89441。这些样本不支持“平滑惩罚压住策略”是主要原因，不据此删除平滑约束。

### 相同轨迹前缀的离线重评分

保持真实记录到首次5°越界的全部连续奖励，将−10放在该时刻，并删除后续回报；不生成新动作、不重新仿真、不修改成功判据。

## 动作执行链：轮限幅牵连腿残差

固定使用接触后0.3秒（600物理步）窗口，避免各回合长度不同导致比例误判。电机顺序为左腿两关节、右腿两关节、左右轮。所有入口窗口的速度限幅命中都在左右轮，四个腿关节没有命中；但 `invalid_base` 会令统一λ=0，腿残差也一起取消。

| 策略/场景 | 全局清零比例 | 清零但非零残差可行步数 | 其中完整请求可行步数 | 左/右载荷加权切向滑移 m/s |
|---|---:|---:|---:|---|
| 原700000 | 0.83% | 2 | 2 | 0.381 / 0.293 |
| 原700102 | 42.83% | 209 | 209 | 0.658 / 1.030 |
| 原700202 | 80.17% | 106 | 103 | 2.079 / 1.072 |
| 原700302 | 82.33% | 83 | 82 | 2.012 / 1.653 |
| 六维700000 | 30.17% | 181 | 181 | 0.008 / 1.078 |
| 六维700102 | 37.33% | 212 | 212 | 0.641 / 0.897 |
| 六维700202 | 71.33% | 264 | 264 | 2.184 / 0.758 |
| 六维700302 | 80.50% | 75 | 71 | 1.812 / 1.300 |

可行性按**已限幅的基础扭矩**加同一请求残差，在所有原电机速度边界内求统一λ；非零条件λ>1e-6，完整请求条件λ≥1−1e-6。这只证明瞬时边界有余量，不证明残差方向稳定、未触发其他映射保护，或闭环能成功。成功样本也有37.33%的入口清零，故不能把清零/滑移与失败的相关性当作充分因果证据。本轮不移除该保护、不扩大力矩包络。

## 下一步与训练准入

1. 优先做**失败反馈对齐**的单因素受控原型：首先验证一次性越门信号、无重复惩罚、奖励排序边界及训练/评估分离。网络、M3动作、观测、地形、指令、权限和PPO配置固定；不能同时加预瞄、放宽KL或修改控制限幅。现有离线重评分只是该原型的动机，不能直接晋升为默认奖励。
2. 评价始终运行完整轨迹，保持全过程5°门、完整率、接触/通过证据和原场景回归；训练提前结束不得冒充“完成”。先有可重复的困难场景成功证据和原型工程检查，再决定是否值得进行1024并行、等预算的学习对照。
3. 全局清零中仍可行的残差作为独立后续控制假设。若前一因素无净收益，再做固定策略、原边界下的最小执行链消融，不把两个因素合并后归因。
4. 正式训练尚未成熟，本轮未启动。强验收继续为困难组提升≥20个百分点、成功≥85%、完整≥95%、多次/独立批次稳定及原能力不退化；达到开发门后才开全新留出。正式训练仍须1024并行、保留动画与全部环境总览、打开窗口、连续3轮无改善停止且最多10轮。

## 复核入口

在项目根目录使用 `.venv/bin/python wheelleg_warp/trace_failure_chain.py --analyze-only --output wheelleg_warp/results/failure_chain_20260922` 可从八个NPZ重算事件、奖励、限幅与同前缀重评分，并运行断言，不运行物理或更新权重。`--check`执行短GPU非侵入对照；`--output`指定不存在的新目录可重新采集，不能覆盖归档。

`summary.json`分别保留采集时源文件哈希和当前离线分析器哈希，后续只扩展分析字段没有重采物理数据。当前脚本包含完整采集和复核路径；数值相同不作为接触仿真跨批次逐位复现保证。
