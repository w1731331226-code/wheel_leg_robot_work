# 任务契约 v2：轮/腿残差分组余量闭环消融

## 结论

**分组方案未通过能力门，不晋升。** 固定 terrain-v3 M3 检查点、160 个公开开发世界、同后端与任务契约，按原分配 A→分组 B→B→A 串行完整回放。困难台阶成功为 A 34/48、B 35/48、B 35/48、A 33/48；困难组完成分别 44/48、43/48、43/48、41/48。四个 24/27 mm 低速选定世界，B 两轮全部失败；原回归与 mixed 每轮分别 16/16、12/12。相对原 GPU 已公开 35/48 成功的参照没有稳定大幅收益，仍未达到至少 45/48 成功、46/48 完成的准入门。

## 单变量与工程核验

- 新 `grouped_residual=False` 默认关闭，仅允许 diff3 且不得叠加旧 `project_clipped_base`。实验组只把同一个 M3 残差的腿部四电机与轮部两电机分别求可行缩放；保留各组内原方向和原指令边界、固定权重/归一化、2 kHz 基控制、速度命令、地形、奖励与姿态门。`diag`/终态的单个 λ 字段是两组 λ 的较小值，**不表示分组后腿部实际执行比例**；执行电机残差仍逐路记录。
- [旧投影工程检查](existing_projection_check.json)：1006 组 GPU 边界/异常向量、非绑定 1 秒配对和非有限控制保护通过。默认控制器 [12000 物理步 CPU/GPU 对照](default_cpu_gpu_check.log)通过，最大扭矩差 `4.70×10⁻⁷`。
- [分组工程检查](grouped_engineering_check.json)：非绑定 1 秒与默认环境观测/奖励配对；单世界完整 GPU 回放有 548 个“共同 λ 为 0、腿部仍执行非零残差”的子步，六路**名义指令**包络最大超额为 0，回报总和匹配终态。它证明选项实际生效，不证明实测电机力矩硬限、硬件安全或任务能力提升。
- [原动画采集入口一步烟测](live_smoke_check.json)通过，仅验证默认控制调用链可执行；没有启动 PPO 训练或录制正式动画。
- [配对协议](paired_160/protocol.json)锁定公开面板、检查点及本次源码哈希；逐世界原始终态保存在 `paired_160/run_01.json`～`run_04.json`。未读历史最终 64 例，也未打开 720000～723999 留出；没有新 PPO 更新。

## 决定与下一步

默认共同 λ 保持不变；分组选项仅留作明确标注的复现实验，不用于训练/部署。旧“去掉基础限幅后硬清零”与本次“轮/腿分组”是两个单独因素，二者均未提供强门所需的稳定能力提升。下一步优先在同一公开面板定位**未干预世界**的首个物理子步分歧和接触后放大；寻找合法动作时应保存完整可恢复的物理/控制状态，并区分观测不足与实际轮驱动力余量。不得由离线名义余量或小幅总分推断 PPO 算法需要修改，更不得打开最终留出或追加长训练。
