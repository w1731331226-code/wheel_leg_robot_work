# 任务契约 v2：公开高台阶前缀恢复与短时动作探针

## 结论

在固定 160 世界任务契约 v2、terrain-v3 M3 检查点和原**名义电机指令/姿态边界**下，保存了公开失败场景 **700302（27 mm、+0.5 m/s）** 触阶前 `4.46 s` 的 GPU 前缀。`prefix_state.npz` 含 195 个 MuJoCo Warp `Data`、环境及控制数组；新建环境和独立 Python 进程均可从磁盘逐字节恢复全部数组，397 个静态模型数组哈希及批量容量也一致。**数组可恢复，不等于未来轨迹逐位可重复**：同前缀的原动作重放结局和姿态峰值仍有明显数值波动。实际电机扭矩硬限及硬件安全性不由本试验证明。

从该前缀起，将所选世界的 M3 第 1 通道（差动支撑）设为合法归一化值 `+1`，仅持续 30 个 50 Hz 策略步，其余 159 世界、检查点、归一化、速度命令、控制/物理及成功门不改。这是已知地形位置的**特权短时上界探针**，不是可部署的 32 维观测策略。两次干预均未成功；不晋升配置、不训练、不打开 720000 留出。

前缀时两轮进度约 `−0.565/−0.612 m`，尚无目标地形接触。前几个策略步原动作重放相同，随后即使控制输入起点与数组快照完全相同，位置微差仍出现并在接触附近放大；当前不能区分 GPU 求解顺序、未暴露的后端状态或其他数值原因，故不宣称已获得确定性精确续跑。干预改变了动作、接触时间和部分终止类型，但 **0/2 成功**；完整回合和原能力逐例回归均未因此过门。

## 证据与下一步

`protocol.json` 冻结源码、面板和策略文件哈希；`prefix_manifest.json` 记录 195 个状态数组、397 个静态模型数组哈希、世界容量与快照摘要；`prefix_state.npz` 是实际磁盘快照。`run_01.json`～`run_04.json` 保存逐 50 Hz 行为与终态，`summary.json` 保存同进程数组恢复验收；`cross_process_baseline.json` 验证独立进程恢复并保留不同终止的失败证据。数组恢复在每次重放前逐字段、逐字节核对，并未只校验 qpos/qvel。

下一步要以同前缀多次 A/A 重放给出背景波动，再对事先限定的动作候选做**重复、同批的短时对照**；任何单次通过都不能直接晋升。若合法动作始终不能稳定通过，再区分轮电机包络、缺少接触/地形观测与任务本身的可达边界。当前不修改 PPO，也不把本机 GPU 物理吞吐写作 PPO 端到端加速。
