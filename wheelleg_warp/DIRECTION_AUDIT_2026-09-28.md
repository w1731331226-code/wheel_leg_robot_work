# 当前论文与地形研究方向审核（2026-09-28）

## 判断

**保留“不对称接触下差动动作对航向—速度折中的作用”作为可证伪问题；暂停把当前 M3＋PPO 视为已有方法贡献。** 近期 Warp 高台阶实验没有证明候选优于原 GPU 策略，也没有找到让公开低速 27 mm 场景稳定满足 5° 门的固定合法脉冲。下一阶段的最大信息增益来自**可观测性、反应时间和受约束动作可达性**，目前没有针对 PPO 损失、网络规模或额外训练步数的因果依据。

论文计划的唯一主指标是完整任务的航向误差 `Jψ`，同时保护成功率、速度和姿态；近期 Warp 任务的准入主门是困难台阶成功/完成数。二者场景、检查点和后端均不同，不能将 Warp 的某次台阶总分当作 CPU 航向论文的 `Jψ` 优势，也不能在看到结果后把一项失败转写成另一项成功。若最终决定以地形接触控制为主论文，应另行预注册问题、强对照和主指标，保留现有协议与失败记录。

### 为什么“接触后再让 PPO 修正”风险很高

`native/environment.py` 的 32 维 Actor 观测包括姿态/gyro、机身速度、四关节角速、左右轮速、腿长/腿速及**实际执行**残差；没有显式地形距离/高度、左/右轮目标地形接触位或轮地面力。XML 中已有 `wheel*_ground_force` 仿真传感器，但当前 Actor 和基控制器都没有读取其接触力；能否在硬件获得等价信号也未验证。现有轮速、gyro、执行残差可能间接透露冲击，**是否够早、误报多少尚未检验**，不能把“没有显式位”直接写成“完全不可观测”。

[既有 700102 的带仪器回放](results/policy_trace_pair_v2_20260923/)可作时序线索：首次目标接触为 `4.5165 s`，记录中约 `4.54 s` 的 Actor 输入已出现明显左右轮速差（约 `5.35/12.35 rad/s`），首次 5° 越界在 `4.7945 s`。该 21 mm 世界与 700302 的 27 mm 低速任务、延迟和结局不同，不能据它宣布 700302 也有充足反应时间；它说明所需审计必须逐场景对齐**动作使用前的延迟观测**与 2 kHz 真实接触，而非把步末状态当作 Actor 当时已知的信息。

Actor 每 20 ms 才发一次动作，输入又按场景延迟 0～20 ms；700302 的冻结延迟为 3.5 ms。2 kHz 基控制器读当前 gyro、关节/轮速，但同样不直接读取接触位。`native/controller.py` 每个 0.5 ms 物理步最多将一个归一化动作分量推进 `0.01`，所以从 `−1` 变到 `+1` **至少 100 ms**；这只是目标滤波下界，还未计轮电机转速余量。700302 的**固定 `−1` 脉冲回放**在 50 Hz 记录中左轮/双轮首次接触分别约 `5.04/5.06 s`，姿态累计峰值首次超 5° 约 `5.08 s`。真实 2 kHz 事件时间在这些 50 Hz 桶内，不能精确宣称只有 40 ms；但数量级明显短于完整动作反向所需时间。一次超过 5° 会写入累计峰值，后来恢复姿态也无法挽回本回合 `success`。因此只加一个接触位给 50 Hz Actor 未必来得及，必须先测**接触前可用信息**或 2 kHz 反馈可行性。

### 其他高优先级问题

1. **物理/动作权限未闭合。** 接触后轮速包络常使共同 λ 接近零；离线显示腿部单独有名义指令余量，但分组闭环没有强收益。M3 轮差矩只做左右相反输入，不能直接增加两轮共模驱动力；低速 24～27 mm 是否在当前命令、姿态和实际电机扭矩下可达，仍无充分证明。`control_limit_scope=nominal_command`，实际执行力矩硬限及模型碰撞覆盖不能由指令限幅自动推出。
2. **强对照与新颖性。** [已有文献矩阵](../wheelleg_ppo/LITERATURE_MATRIX.md)覆盖双轮腿 LQR/WBC、VMC＋自调 LQR、残差 RL、接触规划及动作空间研究。“PPO＋VMC/LQR”“低维差动”“GPU 地形课程”单独不新。若要主张本任务的差模先验，至少要让 B1、M1、M3、同维 N3±、B2-V 同观测、同预算、同后端比较；经典接触感知/轮速反馈也应认真作为基线。
3. **开发集过度使用。** 700302 和旧 64 例已经反复用于机制检查；它们只能是公开开发材料。不得用它们的最低峰值选模型，也不得打开 720000～723999 最终留出作阈值或动作时序调节。
4. **证据来源与时间表。** 原 CPU 航向预实验的阶段目录在当前工作区缺失，而计划文字仍有历史“运行中”叙述；正式论文前须找回对应检查点/配置/日志或在新目录按冻结协议重做，不能只引用文字分数。距计划的 11 月中旬投稿还有约七周；同时推进 3600 万步六方法预实验和未闭合的高台阶能力，风险高，应先设一周内的研究停走门。

## 下一步：按证据门推进

### 第 1 阶段：观测与时序审计（先做，只读）

在**已公开的** 160 世界面板中分层取 24/27 mm 不同速度/方向及原场景、低台阶控制，保持同一 GPU 批次和检查点。只记录必要世界的 2 kHz 左右轮首次接触、轮速/gyro/实际残差、λ 与名义/实际力矩，以及每次 50 Hz Actor 真正收到的 32 维**延迟后**观测和实际下发动作。对每例给出：`首次可区分的观测信号 → 下一策略动作 → 滤波后可执行残差 → 首次 5° 越界`的时间线；分别报告接触前与接触后信号及平地/对称场景误报。先以固定、简单的轮速差/gyro 规则作离线可检测性检查，不训练新网络，也不改观测或控制链。

**出口：**若有可靠、可获得的信号且其提前量覆盖动作滤波与轮速包络需要的反应时间，进入第 2 阶段；若只能在触阶后观测到、并晚于不可逆越界，当前 50 Hz Actor 事后反应的假设不成立，先设计可实现的预瞄信息或 2 kHz 基控制反馈，并单列为**新协议**。不能直接把模拟器接触真值塞进 Actor 后仍称本体感知。

### 第 2 阶段：单因素可达性与控制对照

先将**模拟器特权接触/位置 oracle**与**仅使用上述真实可得信号的最小反馈规则**分开，固定 160 世界任务、M3、速度命令和电机/姿态门，预注册少量动作或分配候选，并对每个候选做 A/A 背景、A/B 配对重复与一次共同世界重排。报告逐例胜负、完整率、峰值裕度和原场景回归，不只报总成功数。若 oracle 稳定成功而可得信号规则失败，瓶颈在信息/反应；两者都失败，优先查动作与物理约束；简单规则成功，则该规则成为强经典对照，PPO 必须再证明额外收益。

**出口：**公开 48 困难台阶以原 GPU 35/48 为同任务参照，候选至少 45/48 成功、46/48 完成，且原场景逐例不退化并跨重复稳定，才值得准备新开发面板。未过门即报告负结果，不启动 1024 世界长训。这里的多次同前缀重放只是相关数值扰动，不能当多个独立场景种子。

### 第 3 阶段：决定论文主线，再决定 PPO

- 若第 2 阶段证明了可靠、可观测且强于手工反馈的行为，冻结新开发/原回归/最终留出，按原计划比较 M1/M3/N3±/B2-V 与强经典，**PPO 仍用标准实现**；只有动作可达、信息充足而标准 PPO 跨种子仍学不会时，才针对 KL、价值拟合或奖励做一次独立修改。
- 若只有特权 oracle 能过门，应改研究问题为接触感知或可行控制的系统研究，并与现有接触触发/模型控制文献区别；不能把当前 M3＋PPO 直接称为已验证创新。
- 若连受约束 oracle 都无法稳定过门，缩题为物理/执行器边界与失败机理，不再承诺“提高高台阶成功率”；保留原 CPU 航向协议作为独立候选，但同样须找回原始证据并通过其 `Jψ` 和强对照门。

**本审核不改冻结任务契约、成功门、权重或 PPO。** 纯仿真可支持方法研究，当前证据不足以承诺 SCI/EI 录用或实机安全；研究是否成立取决于下一阶段的可观测、可达与配对优势证据。
