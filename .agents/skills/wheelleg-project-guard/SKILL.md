# 轮腿项目任务约束

项目根目录：`/home/wmt/wheel_leg_robot_work`。以下路径相对此根目录。用户最新明确要求优先于历史计划；约束减少无效工作，不减少必要验证。

## 每项任务

- 先确定本轮交付物、对应计划阶段、验收条件；简单任务在内部完成判断，不另写计划文件。只做交付所必需的工作。“继续”沿当前未完成项推进，不自动启动训练、转做ROS2或扩充论文数量。
- 先用已有上下文和下面入口定位，只读相关小节及直接证据。正文/日志先搜索再截取；默认排除results、backups、缓存和二进制，需对照时再指定文件。禁止每轮遍历整个工作区、重读全部技能/报告或倾倒长JSON。
- 复用现有实现。改逻辑前查调用者和真实输出链，只改根因；不为可能的未来需求新增依赖、框架、迁移或抽象。完成验收即停止，不附带重构和扩大测试。

## 按需入口

| 任务 | 只按当前问题读取 |
|---|---|
| PPO目标/协议/训练决策 | `wheelleg_ppo/PAPER_PLAN.md`的范围、对照、继续门和当前状态 |
| 控制/环境修复 | `wheelleg_ppo/PREPPO_FIX_REPORT.md`及其对应代码、JSON；旧准入报告只作历史证据 |
| 文献 | `wheelleg_ppo/LITERATURE_MATRIX.md`；获取记录`LEGAL_ACCESS_SEARCH.md`、全文核对`LITERATURE_FULLTEXT_REVIEW.md`/`CRRL_FULLTEXT_REVIEW.md`均在同目录 |
| ROS2 | `wheelleg_ros2/GRADUATION_PLAN.md`；用户明确恢复才推进，禁止整个控制目录同步 |

## 研究硬约束

- PPO默认纯仿真、地面不对称接触、VMC＋六状态LQR＋差模残差；跳跃保留回归，ROS2独立。用户明确改变范围时更新对应计划，不用旧范围反复阻拦。
- 长训练前核对最新基线和主门是否可达。已有记录指出困难组12/12使“再提高10个百分点”不可达；以最新证据确认，未解决时先处理协议问题，不盲跑20万/200万步。不能弱化基线、事后换主指标或用最终保留集选场景/调参。
- 固定名义设计与随机被控对象分离；输出顺序为六状态覆盖→残差→最终限幅→物理步，计时一次。仅改文献不触碰控制代码。工程通过、学习收敛、方法优势和实机安全分开陈述。
- 历史基线、哈希和失败记录不覆盖；新实验使用独立输出目录，检查脚本默认输出位置。复用结果须核对相关源码/配置/协议是否一致；日期新不等于证据有效。

## 成本与停止条件

- 检索先查已有获取记录。默认一轮定向搜索＋一轮有新线索的跟进；已确认权限阻塞则记来源并继续不依赖它的工作。没有新入口不重复搜同义词、轮换浏览器或下载同一文件。用户明确要求深入搜索可扩大范围，但每轮须获得新证据。
- 回归按影响选择：文档只核对事实/链接；局部逻辑跑最小相关检查；控制/模型/输出链改动再跑受影响集成回归。成功且相关代码未再变，不重复跑；耗时测试串行，普通独立读取可批量。
- 不默认开子代理、另建任务或调高推理/模型；用户明确要求时再用。无进展不忙轮询；保存日志，结束时读摘要/失败尾部。
- 有状态变化才改现有状态入口，避免每轮新建报告、重复矩阵和全目录哈希。阶段报告或用户明确要求除外。
- 默认最终回复至多4个短要点：完成项、验收证据、未关闭项、必要下一步；附关键文件链接。不复述工具流水账，不估算未经测量的token节省。用户要求详解时给足细节。

## 长期记忆与交付同步（用户明确新增约束）

- 项目任务先按需读取根目录 `PROJECT_MEMORY.md` 当前状态/未完成项。每轮大的对话收尾记录变动、决定、证据和后续，及时中文提交；每次提交均需更新该文档并通过本地提交钩子。
- 编辑期间暂停 `wheelleg-git-sync.service` 或持有 `.git/project-write.lock`，收尾恢复守护并核对远程。同步失败保留本地提交、明确报告，不强推。
- `wheelleg_warp/` 是独立GPU物理基线，原CPU实现与历史效果为校对参照；GPU物理吞吐和PPO端到端性能必须分开实测、表述。
